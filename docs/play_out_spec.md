# 局の途中からのプレイアウト（`play_out`）

2026-11-19 に仕様を作り、2026-11-20 に第 1 版を実装しました（`src/rust/playout.rs`、`src/python/yamawake/playout.py`、テストは `tests/playout/`）。
最初の要求元は tide の段階 1 のラベル作りです（tide リポジトリの `docs/decisions.md` の D47）。ただし、それだけに限らない汎用の入口として作っています。

## 1. 目的と方針

局の途中の局面を与え、内蔵のボット（既定は suzume 4 人）に Rust の中で局の終わりまで打たせ、局末の結果を返します。
たくさんの局面をまとめて渡すと、並列に処理します。
1 判断ごとに Python を経由しないので、Python にかかっていた分がなくなります。
局面ごとの処理は互いに独立しているので、速さはコア数にほぼ比例します（6 節）。

一般性を保つため、次の方針で作っています。

- **局面を共通の部品にする**：局面（3 節）を 1 つの形で定め、合法手の列挙、ボットの選択、プレイアウトのどれもが同じ局面を受け取ります。将来の「局の途中から始める対局ループ」（9 節）も同じ局面から始める予定です。
- **隠れた牌の指定は自由にする**：隠れた牌（手牌、山、王牌）は、全部を与えても、一部だけを与えても構いません。与えなかった分は、乱数の種から一様に埋めます。
- **牌山は 2 つの形を選べる**：普通の牌山（1 つの山を順にツモる）と、分割牌山（席ごとのツモの列。arena の既定と同じく、副露してもツモがずれない）の両方を扱います。
- **強制する手は列にする**：指定の席の「次の判断から k 個」を強制できます。k = 1 が普通の使い方で、k = 0 なら強制せずにボットだけで打ちます。
- **打ち手は席ごとに選べる**：席ごとに、内蔵のボットのどれでも、オプション付きで指定できます。

### 使い方の例：tide の段階 1

- 開始局面は、人の牌譜（天鳳鳳凰卓を tide の codec で mjai にしたもの）の局面です。
- 指定の手の候補は、打牌の判断なら立直しない打牌と立直宣言の打牌です。副露の判断なら、チー（使う搭子ごと）、ポン、見送りです。
- 候補ごとに、同じサンプルの上で、続きを suzume 4 人が局末まで打ちます。
- ラベルは、指定の席の局末の点数の変化です。
- 候補は `legal_actions` で作り、suzume の選択は `seat_options` で得ます。
- 規模は、1 回の呼び出しで 1,000〜10,000 組（開始局面 100〜1,000 × 指定の手 約 10 × サンプル 1 つ。雑音を測るときはサンプル 8 つ）です。

``` python
from yamawake import legal_actions, play_out, seat_options

p = {"events": events, "seat": 2}                       # その局の start_kyoku からの mjai のイベント
opts = seat_options([p])[0]                              # {"legal": [...], "choice": suzume の手, "scores": [...], ...}
cands = [m for m in opts["legal"] if m["type"] in ("dahai", "reach")]
res = play_out([{**p, "actions": cands, "samples": [{"seed": 0}]}])
labels = [res[0][a][0]["delta"][2] for a in range(len(cands))]  # 候補ごとの、席 2 の局末の点数の変化
```

## 2. 入口の一覧

| 入口 | 返すもの | 版 |
|---|---|---|
| `legal_actions(position)` | 指定の席の今の判断で合法な手の一覧（mjai の形） | 1（実装済み） |
| `seat_options(positions, player="suzume", threads=None)` | 局面ごとに、合法な手の一覧、ボットが選ぶ手、suzume では手ごとの点数 | 1、2（実装済み。点数は 0.16.0 から） |
| `play_out(positions, players="suzume", split_wall=False, threads=None, record_events=False, record_samples=False, on_error="raise")` | 局面 × 指定の手 × サンプルの組ごとの局末の結果 | 1（実装済み） |
| `SelfPlayLoop.from_positions(...)` | 局の途中から始める対局ループ（一部の席を Python のプレイヤーが打つ） | 3 |

- どれも `yamawake` から import します。
- まとめて処理する入口（`seat_options`・`play_out`）は、GIL を外し、rayon で並列に処理します。`play_out` は（局面, サンプル）の組ごとに局面を 1 回だけ組み立て、それを複製して指定の手それぞれでプレイアウトします。

## 3. 局面

1 つの局面は次の欄を持つ dict です。

| 欄 | 中身 |
|---|---|
| `events` | その局の `start_kyoku` からのイベント（mjai の dict か JSON の行）。他家の配牌・ツモは `"?"` に伏せてもよい |
| `seat` | 指定の席：`actions` の手を打つ席（0〜3）。局の開始の席（親）や、局面の時点で手番の席とは限らない。`actions` がすべて空の列なら省ける |
| `actions` | 指定の手のリスト（下記）。`play_out` が使う。省くと `[[]]`（強制しない 1 通り） |
| `samples` | 隠れた牌のサンプルのリスト（下記）。`play_out` は各サンプルで、指定の手のそれぞれでプレイアウトする。省くと `[{}]`。`legal_actions`・`seat_options` は最初のサンプルを使う |
| `hand` | `legal_actions`・`seat_options` 用：指定の席の手牌（`events` がその席の牌を伏せているとき） |

- 点数・本場・供託は `events` から読みます。値は `start_kyoku` の値に、その後の立直棒などを反映したものです。別の欄では受け取らず、食い違いが起きないようにしています。
- `events` は `start_kyoku` だけでも構いません。この場合は、親の最初のツモ（山の最初の牌）の後の局面になります。
- 局面の時点で誰の判断になるかは、エンジンが `events` から決めます。
  - 他家の `dahai` の後で誰も鳴けない場合など、判断の前にツモが要るときは、サンプルの山からツモって進めます。
- `events` の中で `hora`・`ryukyoku`・`end_kyoku` は受け付けません（局が終わった後の局面）。`reach_accepted` と `dora` は読み飛ばし、エンジンが自分で出します（7 節）。

### サンプル

各サンプルは、局面の時点での隠れた牌を決める dict です。どの欄も省けます。
牌は mjai の表記で書きます（`"1m"`〜`"9s"`、`"E"`・`"S"`・`"W"`・`"N"`・`"P"`・`"F"`・`"C"`、赤は `"5mr"`・`"5pr"`・`"5sr"`）。牌の物理的な番号（0〜135）は yamawake が割り当てます。

| 欄 | 中身 |
|---|---|
| `hands` | 席ごとの手牌（副露を除いた手の中の牌）。4 つのリスト（与えない席は `null`）か、`{"席": リスト}` の dict。枚数はその席の今の枚数ちょうど |
| `wall` | 普通の牌山の残りの山（ツモの順）。`split_wall=False` のとき。先頭の何枚かだけでもよい |
| `wall_queues` | 分割牌山の席ごとのツモの列（4 つのリスト、それぞれツモの順）。`split_wall=True` のとき。それぞれ先頭の何枚かだけでもよい |
| `rinshan` | 残りの嶺上牌（ツモの順）。最大 4 − （それまでに引かれた嶺上牌の数）枚。先頭だけでもよい |
| `dora` | これからめくるドラ表示牌（めくる順）。最大 5 − （`events` でめくられたドラ表示牌の数）枚。先頭だけでもよい |
| `ura` | 裏ドラ表示牌。i 番目が i 番目のドラ表示牌の下の牌（これからめくる分も含め最大 5 枚）。先頭だけでもよい |
| `undrawn` | カンで生きた山から外れて引かれない k 枚（下記）。ふつうは省き、`record_samples` の返したサンプルを渡し直すときに使う |
| `seed` | 与えなかった分を埋める乱数の種（整数） |

- **伏せた席**：`events` でその席の牌が 1 枚でも `"?"` なら、その席の配牌とツモはすべて分からないものとして扱います（見えているツモも使わない）。サンプルで `hands` を与えた席も同じで、`events` にその席の牌が見えていても、与えた手牌が優先します。
  - 伏せた席の過去の配牌とツモは、今の手牌と `events` の打牌・副露から逆向きに作り直します（7 節）。
  - 手牌を与えなかった伏せた席は、乱数で埋めます。
  - 立直した席の手牌は、乱数では立直と矛盾しうるので、サンプルで与えてください。与えずに矛盾したときは、そのことが分かるエラーにします。
- **省いた山・王牌**：乱数で埋めます。埋める牌は、見えている牌と、与えた牌・`events` から決まった牌を除いた残りです。先頭だけ与えた山などは、残りを乱数で埋めます。
- 乱数で埋めるものがあるのに `seed` がなければ、エラーにします。同じ局面と同じ `seed` からは、いつも同じサンプルができます。
- 山の長さ：残りツモ数は 70 − （`events` の中の `tsumo` の数。嶺上牌のツモも含む）です。
  - `wall` はこの長さまでです。
  - `wall_queues` は、4 つの列の長さの和がこの値までです。列ごとの長さは自由です。
  - カンが k 回あった局面では、生きた山の最後の k 枚は引かれません。この k 枚はふつう与えず、残りの牌から埋めます（`undrawn` で与えることもできる）。
- 分割牌山を乱数で埋める場合は、局面の後に副露がなかったときのツモの順に、残りの山を席へ順に割り振ります。arena が局の初めに割り振るのと同じ規則です（次のツモの席は、`events` で最後に動いた席の次。`events` が `start_kyoku` だけなら親）。
- **分割牌山のツモと流局**（エンジンの `WallState::draw_split` と `_deal_next`。arena の分割牌山と同じ）：
  - 各席は自分の列から引きます。自分の列が尽きたら、その時点で一番長い列から引きます（同じ長さなら席の番号が大きい方）。借りる先は列の長さだけで決まり、牌の中身は見ません。
  - 流局と海底は、列とは別の、全員で共有する残りツモ数（`drawable_count`）で決まります。普通のツモでも嶺上ツモでも 1 ずつ減ります。
    - 次のツモの番に 0 なら流局です。
    - 0 になる普通のツモが海底、その打牌が河底です。
  - これは普通の牌山と同じ規則です。
  - 山を乱数で（一様に）埋めたサンプルなら、次に引く牌は、どの時点でも、まだ引かれていない見えない牌の中で一様です。したがって、1 回のプレイアウトの結果の分布は普通の牌山と同じです（8 節で確かめた）。
  - 変わるのは、指定の手どうしの相関です。鳴く・見送るで手番がずれても、各席が引く牌は指定の手の間で共通に残ります（tide が副露のラベルの雑音を減らすために使う）。
  - 本当の山や、中身に偏りのある並べ方を与えた場合は、この同等性は保証されません。
- 次の点を確かめ、合わなければエラーにします。
  - 牌の総数：見えている牌と、サンプル・`events` で決まった牌が、それぞれの牌の数（各 4 枚、赤は各 1 枚）を超えない。乱数で埋める場所の数と、残りの牌の数が合う。
  - 手牌の枚数：`events` と合っている。
  - `events` の打牌・副露が、その時点の手牌でできる（エンジンが打ち直して確かめる）。

### 指定の手

`actions` の各要素は、指定の席に強制する手の列です。列の i 番目を、指定の席の i 回目の判断（局面の時点からかぞえて）に打ちます。
1 手だけなら列にせず、mjai の形の dict 1 つで書けます。空の列 `[]` は、強制せずにボットだけで打つことを表します。

| 手 | 形 |
|---|---|
| 打牌 | `{"type": "dahai", "pai": "3m", "tsumogiri": false}` |
| 立直 | `{"type": "reach", "pai": "3m", "tsumogiri": false}`。立直と、その宣言牌の打牌をまとめて 1 手と数える |
| チー・ポン | `{"type": "chi", "pai": "3m", "consumed": ["4m", "5mr"]}`、`pon` も同じ形 |
| カン | `{"type": "ankan", "consumed": [...]}`、`{"type": "kakan", "pai": ..., "consumed": [...]}`、`daiminkan` |
| 和了 | `{"type": "hora"}`。ツモかロンの合法な方 |
| 見送り | `{"type": "none"}` |
| 九種九牌 | `{"type": "ryukyoku"}` |

- 手は `legal_actions` の要素と照らし合わせます。書いた欄だけを比べるので、`consumed` などは省けます。`tsumogiri` を省いた打牌は、ツモった牌で打てるならツモ切りになります。
- 列の手が、その判断の時点で合法でなければ、エラーにします（`on_error="record"` では、その組を記録して次へ進む）。
- 列を打ち終える前に局が終わったら、残りは使わずに結果を返します。結果の `forced` に、実際に打った手の数を入れます。
- 指定の席以外の判断と、列を打ち終えた後の指定の席の判断は、その席のボットが行います。他家の打牌への応答で、指定の席以外にも応答できる席があるときも同じです。
- 例：`[{"type": "pon", ...}, {"type": "dahai", "pai": "9p", ...}]` は、ポンとその後の打牌の両方を指定します（tide は今はポンだけを指定し、打牌は suzume に任せる）。

### `events` の形

- yamawake の arena の牌譜と、tide の codec（`tide_mahjong.mjdata.codec.decode_kyoku`）の出力の両方を、そのまま受け付けます（8 節で確かめた）。
- 読むのは、打ち手の手（`dahai`・`reach`・`chi`・`pon`・`daiminkan`・`ankan`・`kakan`）と、`tsumo` と `dora` の牌です。`reach_accepted` は読み飛ばします。`hora` の `han` など、そのほかの欄は使いません。
- DS1 の見本 10 局（10 節）と arena の牌譜を比べた結果（2026-11-19）：
  - **同じ**：欄の名前、赤の表記、`reach` → `dahai` → `reach_accepted` の順とその直後に他家の鳴きが来ること、嶺上牌のツモが普通の `tsumo` として出ること、暗槓のドラが `ankan` の直後に出ること。
  - **欄の有無だけの違い**：DS1 の `ankan` には `pai` がない（使うのは `consumed` だけ）。DS1 の `hora` に `han` などがなく、`ryukyoku` に `reason` がない（入力には入らない）。
  - **カンドラの時期**：DS1（天鳳）では、大明槓・加槓の `dora` が、嶺上ツモの前、嶺上ツモの後、その次の打牌の後のいずれかに出ます。打ち直しではエンジン自身の規則でめくり、めくる表示牌の中身は `events` の `dora` の順に従います。局面が「カンの後、その `dora` の前」で切られたときは、エンジンの規則でめくるかどうかが決まります。

## 4. 打ち手

内蔵のボット（Rust の中で判断するもの）を、arena のプレイヤーの指定と同じ書き方で指定します。

| 指定 | 例 |
|---|---|
| suzume の組 | `suzume`、`suzume-rla225`、打ち方のパラメータや制限付き（`suzume:aggression=0.5`、`suzume:call=0`、`suzume:call_rate=0.4`） |
| rulebot | `rulebot`、`rulebot:kobalab`、`rulebot:win=0` |
| ツモ切り | `tsumogiri` |

- `play_out` の `players` は、1 つの指定で 4 人とも、または 4 つのリストで席ごとに指定します。`seat_options` の `player` は指定の席を打つ 1 つです。
- 各ボットは、その局の局内の記憶（`SeatMemo`）が空の状態から打ち始めます。
  - suzume の組（A1）の記憶は、計算の記録（DP の解などで、判断には影響しない）と、立直の宣言牌だけです。後者は、立直を 1 手にまとめているので問題になりません。
  - 実際に、arena の対局を途中で切ってプレイアウトすると、残りが arena と完全に一致します（8 節）。
- suzume は同じ入力に対して必ず同じ手を選ぶので、結果のばらつきはサンプルの違いだけから生じます。

## 5. 返すもの

### `legal_actions(position)`

指定の席の今の判断で合法な手を、3 節の指定の手と同じ mjai の形で、すべて返します。`play_out` が合法性を判定する基準と同じです。

- 立直は、宣言できる打牌ごとに `{"type": "reach", "pai": ..., "tsumogiri": ...}` を 1 つずつ並べます。
- チーは、使う搭子（赤の有無を含む）ごとに 1 つずつ並べます。
- 同じ牌の手出しとツモ切りがどちらもできるときは、`tsumogiri` が `false` のものと `true` のものの 2 つを並べます。河の見え方（ツモ切りかどうか）が違い、ボットの判断に影響しうるためです。同じとみなす場合は、呼ぶ側で 1 つにまとめます（tide はまとめてツモ切りの方を使う）。
- 指定の席の手牌は、`events` から作ります。指定の席の牌を伏せた `events` では、手牌を `hand` の欄で与えます。局面に `samples` があれば、その最初のサンプルの上で組み立てます。
- 指定の席の手と見えている牌だけで決まるので、ほかの席を伏せても結果は変わりません（8 節）。
- 指定の席が今判断する局面でなければ、エラーにします。

### `seat_options(positions, player="suzume")`

局面ごとに次の dict を返します。

| 欄 | 中身 |
|---|---|
| `legal` | `legal_actions` の結果 |
| `choice` | ボットが選ぶ手（`legal` の要素のどれか）。立直のときは、宣言牌まで含めた 1 手 |
| `choice_index` | `choice` の `legal` での位置 |
| `basis` | 何が手を決めたか（下の表） |
| `scores` | `legal` と同じ並びの、手ごとの点数（下記）。suzume（A1 の組）以外のボットと、規則で決めた判断では `null` |
| `pmf` | P / M / F の専門家を混ぜる組のときだけ：その判断の状態の確率 `[P, M, F]`（組み込みの `suzume`・`suzume-rla225` にはない） |

点数（suzume、A1 の組。0.16.0 から）:

- 判断の選択肢の上の対数確率（log-softmax）です。最終判断で比べる値そのものを確率に直したもので、`aggression`・`call_shift`・`riichi_shift` を反映した後の値です。
  - 通常は、判断の MLP の出力（logit）に `call_shift`・`riichi_shift` のずれを足した値の log-softmax です。
  - `aggression` が 0 でないときは、(1 − |w|)・元のモデルの logit ＋ |w|・押し（w > 0）か降り（w < 0）のモデルの logit ＋ ずれ、の log-softmax です（対数の方策を混ぜたもの）。
  - P / M / F の専門家を混ぜる組では、専門家ごとの確率を状態の確率で混ぜた値の対数です。
- 立直は、宣言と打牌が 1 つの判断です。立直できる局面の MLP は、「立直せずに切る（聴牌を保つ・崩す）」と「立直して切る」を打牌の種類ごとにまとめて採点するので、`dahai` と `reach` の点数はそのまま比べられます。
- 鳴けるときの判断（チー・ポン・大明槓・見送り）は 1 つの MLP です。鳴いた後の打牌は、次の判断（別の局面）です。
- 暗槓・加槓ができる局面は 2 段です。まず打牌（と立直）の MLP が最善の手を選び、次に槓の MLP が「その手を採る」と各槓を比べます。点数は、槓では槓の MLP の対数確率、それ以外の手では「その手を採る」の対数確率から、打牌の最善手との差を引いた値です（打牌の最善手は、ちょうど「その手を採る」の対数確率になります）。どちらの段が決めても点数の最大が選んだ手になる代わりに、この局面では点数の確率の和は 1 になりません。
- 同じ牌の手出しとツモ切りは同じ選択肢なので、同じ点数です。suzume が打つのはそのうちの 1 つで、`choice_index` が示します。
- `basis` が `"model"` のとき、`scores` の最大の手は `choice` です（同点になるのは上の手出しとツモ切りだけです）。arena の局面 8,733 個 × 5 つの設定で確かめました（8 節）。

| `basis` | 意味 |
|---|---|
| `"model"` | MLP の点数の最善手 |
| `"riichi_group"` | `aggression` があるとき、立直するかどうかは元のモデル（ずれを足した値）の選択に従い、混ぜた点数はその中でだけ比べます。そのため、`scores` の最大が他方（立直するか、しないか）にあることがあります |
| `"win"` | 和了（ツモ・ロン）。合法なら必ず選びます。`scores` は `null` |
| `"kyushu_kyuhai"` | 九種九牌。合法なら必ず選びます。`scores` は `null` |
| `"riichi_tile"` | 立直を宣言した直後の打牌（宣言のときに選んだ牌）。`seat_options` は立直を宣言牌まで 1 手で返すので、ふつうは現れません |
| `"one_discard"`・`"pass"`・`"tsumogiri"`・`"first"` | MLP の手が打てないときの代わりの規則（打牌が 1 種類しかない、見送り、ツモ切り、最初の合法手）。立直後のツモ切りなど。MLP が動いていれば `scores` はその値 |
| `"rulebot"`・`"suzume_rules"`・`"tsumogiri_bot"` | suzume（A1 の組）以外のボット（`legacy-suzume-*` は `"suzume_rules"`）。`scores` は `null` |

### `play_out(...)`

`results[i][a][s]` は、局面 i を、指定の手 `actions[a]`、サンプル `samples[s]` でプレイアウトした結果で、次の欄を持つ dict です。

| 欄 | 中身 |
|---|---|
| `end` | `"hora"` か `"ryukyoku"` |
| `delta` | 4 人の点数の変化。局面の点数（立直棒を払った後）から局末まで。プレイアウトの中で出した立直棒と、得た供託を含む |
| `scores` | 局末の 4 人の点数 |
| `kyotaku` | 局末に場に残る供託の本数（次局へ持ち越す分） |
| `honba` | 次局の本場 |
| `renchan` | 親が続くかどうか |
| `hora` | 和了の一覧：`actor`、`target`、`han`、`fu`、`yaku`、`yakuman`、`deltas`、`ura_markers`（ダブロンは 2 件） |
| `ryukyoku` | 流局のとき：`reason`、`deltas`、`tenpai`（荒牌平局のとき 4 人の聴牌の有無。エンジンの判定と同じ `HandEvaluator::is_tenpai`） |
| `forced` | 強制した手のうち、実際に打った数 |
| `n_decisions` | プレイアウトの中でボットが判断した数 |
| `events` | `record_events=True` のときだけ：局面の後から局の終わりまでの mjai のイベント（エンジンの全情報の牌譜。入力で伏せた席のツモも実際の牌）。嶺上牌のツモには `"rinshan": true` を付ける |
| `sample` | `record_samples=True` のときだけ：局面の時点で決まったサンプル。入力のサンプルと同じ形で、伏せた席の `hands`、`wall` か `wall_queues`（局面の後の残り）、`rinshan`、`dora`、`ura`、`undrawn` をすべて持つ。これを種なしで渡し直すと、同じプレイアウトが完全に再現される |
| `hands` | `record_samples=True` のときだけ：局面の時点の 4 人の手牌 |
| `error` | `on_error="record"` で不正だったときだけ：理由（ほかの欄はない） |

- 次局を配る前で止めます（エンジンの `defer_next_round`）。半荘の終わりまでは打ちません。
- 順位や半荘の終わりの扱いは、呼ぶ側が `scores` などから決めます。
- `events`・`sample`・`hands` を合わせると、局面の後の局の流れと、まだ引かれていない牌が全情報でそろいます（tide がプレイアウトの中の偶然のイベントごとの運の量を測るのに使う、2026-11-20 に追加）。
- 不正な局面は、既定（`on_error="raise"`）では `ValueError` にします。メッセージには、局面・指定の手・サンプルの番号と、理由（`events` の何番目で打ち直せなかったか、など）を入れます。

## 6. 並列と速さ

- 組ごとに別の `GameState` で打つので、組どうしは独立です。結果はスレッドの数にも、処理の順にもよりません（8 節）。
- 測った速さ（2026-11-20、Apple M4 Pro 14 コア、suzume 4 人、arena の牌譜から切った打牌の局面 100 個 × 指定の手 平均 10.7 = 1,067 組、1 組あたりボットの判断 38.5）：

| スレッド | 1 秒あたりの組 | 1 判断あたり（組み立て直しを含む） |
|---|---|---|
| 1 | 166 | 0.157 ms |
| 全コア（14） | 1,555 | 0.017 ms |

- tide の 1 回 1,000〜10,000 組は、この Mac の全コアで約 0.7〜7 秒です。

## 7. 組み立て方

エンジンのイベントの再生（`apply_mjai_event`）は、一発・フリテン・包・嶺上の数などを設定しない簡単なものです。そのため使わず、局面をエンジンの通常の進行で作り直します。

1. **イベントを読む**：`start_kyoku` と、打ち手の手・ツモ・ドラを読みます。ツモが嶺上牌かどうかは、同じ席のカンの直後か（`dora` を除いて）で決めます。
2. **サンプルを決める**：見えている牌（河、副露、めくられたドラ表示牌、伏せていない席の手牌）を数え、サンプルで与えた牌を除き、残りを `seed` の乱数で並べて、与えなかった場所に置きます（手牌、山、嶺上牌、ドラ表示牌、裏ドラ表示牌、引かれない k 枚の順）。
3. **伏せた席の過去を作り直す**：伏せた席の配牌とツモを、今の手牌から `events` を逆にたどって作ります。
   - ツモ切りの打牌は、その直前のツモの牌です。カンの直前のツモは、その槓の牌です（立直中の暗槓はツモった牌でしかできないため）。
   - ほかのツモは手の中の牌から選びます（直後に手出しした牌そのものは選ばない）。どれを選んでも、局面での状態（手牌、フリテン、聴牌）は変わりません。
4. **牌山を並べる**：配牌、過去のツモ（ツモの順）、残りの山、王牌（嶺上牌、ドラ・裏ドラ表示牌の位置）を、エンジンの牌山の並び（`WallState::load_wall`）に置き、牌の物理的な番号を割り当てます。
5. **局を始めて打ち直す**：`GameState::_initialize_round` でその牌山の局を配り、`events` の手を順に `step` で打ちます。
   - ほかの席の応答は見送りにします。
   - ツモはエンジンが牌山から引くので、`events` の牌と同じかを確かめます。
   - 分割牌山では、局を始めた後に、席ごとのツモの列（過去のツモと残りの列）を置きます。
   - こうするとフリテン・一発・第一巡・包・喰い替え・王牌の数などを、エンジン自身が通常の対局と同じに決めます。
6. **プレイアウト**：組み立てた局面を複製し、局が終わるまで `step` を繰り返します（arena と同じ `GameSlot` を使う）。
   - 指定の席の判断には、強制する手の列を順に適用します。立直は、宣言と打牌の 2 つの `step` で適用します。
   - それ以外の判断は、arena と同じ内蔵のボットの判断（`GameSlot::bot_action`）で決めます。ボットに渡すその局のイベントは、エンジンが打ち直しとプレイアウトで出したものです。
   - エンジンの `defer_next_round`（yamawake のパッチ。既定は無効で、そのときは元のエンジンと同じ）により、局が終わったところで、次局を配らずに止まります。
7. **結果**：局末の点数と、`hora`・`ryukyoku` のイベントから 5 節の結果を作ります。

`legal_actions` と `seat_options` は、手順 1〜5 までを行い、エンジンの合法手（とボットの判断）を mjai の形に直して返します。立直は、局面を複製して立直を宣言し、その後の合法な打牌を並べます。
