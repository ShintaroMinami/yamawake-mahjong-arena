# suzume：教師に合わせた MLP で判断するボット

suzume は、強化学習で得た強いエージェント（教師）の方策に合わせて、判断ごとの小さな MLP で打つボットです。教師は arena で強さを測る相手としては遅いので、速いボットを教師に近づけて、測る相手にすることを目的にしています。

このファイルは、今の設計の説明です。決定の経緯、試した案、当時の測定値と、学習の手順は、このリポジトリに含めていません。

- コード：`src/rust/suzume/`（Rust）、`src/python/yamawake/suzume.py`（Python からの入口）
- 固定のパラメータ：`params/`
- 学習のスクリプト・データ・手順：このリポジトリには含めない（学習の段階は 2026-10-14 に終えた）

## 1. 判断の流れ

判断ごとに、次のルールを上から順に試し、最初に答えたルールが打ちます（`src/rust/suzume/registry.rs`）。

| ルール | 判断すること |
|---|---|
| `win_always` | 和了できれば必ず和了する（ツモ・ロン） |
| `kyushu_always` | 九種九牌を選べるときは必ず流局にする |
| `pf_discard` | 押し引き（`pf=1`、既定。8 節）：自分の手番の打牌で状態（P・M・F）を予測し、M なら回し打ち、F ならベタオリのモデルで切る。P と立直できる判断は後のルールに任せる |
| `fold_discard` | 他家の立直を受けたときのベタオリ（`fold=1`・`pf=0` のときだけ。他家 3 人全員について採点する。7 節） |
| `kan_mlp` | 暗槓・加槓。カンの MLP が、その判断の本来の選択よりカンを高く評価したときだけカンする |
| `universal_mlp` | 打牌、立直・ダマ、副露（チー・ポン・大明槓・見送り）を、判断ごとの MLP で選ぶ |
| `discard_forced` | 合法な打牌が 1 つしかないとき（立直後のツモ切りなど） |

どのルールも答えないときは、見送りが合法なら見送り、そうでなければツモ切り、それもなければ最初の合法な打牌を選びます。

`pf=0` の自己対戦（suzume ×4、九種九牌の `kyushu_always` の前の測定）では、判断の 94.8% を `universal_mlp`、3.2% を `discard_forced`、1.8% を `win_always`、0.2% を `kan_mlp` が決めています。

## 2. オプションと固定のパラメータ

外から変えられるのは、次の 6 つだけです（`src/rust/suzume/config.rs`）。それ以外を指定するとエラーになります。

| オプション | 意味 | 既定 |
|---|---|---|
| `kan` | 0/1：カンする（暗槓・加槓はカンの MLP、大明槓は副露の MLP が選ぶ。立直後の暗槓を含む） | 1 |
| `call` | 0/1：チー・ポンする。0 ならチー・ポンを選ばない（大明槓は `kan` に従う） | 1 |
| `riichi` | 0/1：立直する。0 なら立直の選択肢を選ばず、DP も立直を前提にしない | 1 |
| `fold` | 0/1：他家の立直を受けたらベタオリする（7 節。`pf=0` のときだけ効く） | 1 |
| `fold_shanten` | 0〜8：`fold=1` のとき、ベタオリに入る打牌後の最小向聴 | 1 |
| `pf` | 0/1：押し引き（8 節）。1 なら `fold` と `fold_shanten` は使わない | 1 |

指定の仕方：`--players suzume:call=0 rulebot`、`--opt kan=0`、Python では `SuzumeAgent({"riichi": 0})`。

モデルが学習した前提の値は、オプションにせず、`params/` のファイルに置いています。ビルドのときに取り込み、最初の利用で 1 回だけ読みます（`src/rust/suzume/params.rs`）。値が欠けていたり、知らない名前があったりすると、すぐにエラーで止まります。変えるには、ファイルを直してビルドし直します。

| ファイル | 中身 |
|---|---|
| `params/suzume.json` | DP の定数（DP を使う最大の向聴 2、ロンの倍率 0.3、立直棒 1,000 点）、鳴いた後の打牌を選ぶ価値の特徴量の重み、その帯の中の選択の帯と重み、単独トップの判定の点差（`suzume-mlp1` のモデルの外の切片が使う） |
| `params/hand/<組>/` | 手組みのモデルの一揃い（11 ファイル、下の表） |
| `params/state/<名前>.json` | 押し引きの状態予測モデル（`pf=1`）：入力の名前の順（ベタオリと同じ 38 個）、状況の入力 `sit_inputs`（21 個、ないものもある）、標準化、重み。任意で状態ごとの係数 `state_weight`（既定 1） |

手組みのモデルの一揃い（`params/hand/<組>/`。名前の `P`・`M`・`F` は押し引きの状態、8 節）：

| ファイル | 判断 |
|---|---|
| `discard_P_12.json` | 打牌（打牌後の最小向聴 1〜2）。P |
| `discard_P_3.json` | 打牌（打牌後の最小向聴 3 以上）。P |
| `discard_P_t.json` | 立直できない聴牌（ダマか崩すか）。P |
| `discard_M.json` | 回し打ちの打牌（M の打牌と聴牌の判断）：ベタオリと同じ形 |
| `discard_F.json` | ベタオリの打牌（F の打牌と聴牌の判断、`fold=1`）：入力の名前の順、標準化、MLP の重み、他家ごとのスコアの組み合わせ方（`combine`、ソフトな最小の τ）、待ちである率の表とその帯の境界、巡目・最後に切られてからの打牌数の上限、早い打牌の数 |
| `riichi_P.json`・`riichi_M.json` | 立直できる判断（P、M と F） |
| `call_P.json`・`call_M.json`・`call_F.json` | チー・ポン・大明槓（P・M・F） |

## 3. 全判断共通の特徴量 U

判断のすべての選択肢を、同じ特徴量の組 U の 1 行で表します（`src/rust/suzume/universal.rs`、76 列）。MLP はこの行を入力にします。

### 判断の種類と選択肢

| 判断 | 選択肢 | 選択肢の後の手（A） | 値 |
|---|---|---|---|
| `discard`（打牌後の最小向聴 1 以上） | 合法な打牌ごと | 打牌の後の 13 枚 | DP の行（向聴を保つ打牌、最小向聴 2 以下） |
| `riichi`（立直が合法） | 聴牌を保つ打牌ごとのダマ、聴牌を崩す打牌（`break`）、聴牌を保つ打牌ごとの立直 | 打牌の後の 13 枚 | ダマ・立直の DP の行（立直は立直棒の損を引く）。崩す打牌は 13 枚の DP の値 |
| `tenpai`（打牌後に聴牌、立直は合法でない） | 打牌ごとのダマ・崩す打牌 | 打牌の後の 13 枚 | ダマの DP の行 |
| `call`（チー・ポン・大明槓が合法） | 見送り、各チー・ポン・大明槓 | 見送り：今の 13 枚。鳴き：鳴いた後、続く打牌の後の手 | 見送り：次のツモからの DP の値。鳴き：続く打牌の DP の行 |
| `kan`（暗槓・加槓が合法） | 「カンしない」（その判断の MLP が選ぶ選択肢の行。立直後はツモ切り）、各カン | カン：カンを副露に足した手、次は嶺上牌のツモ | カン：DP の値（新ドラは数えない） |

鳴いた後の打牌は、DP の範囲なら DP の値が最大の牌、範囲外なら価値の特徴量のスコアで選びます（`rules/calls.rs`、`rules/value_features.rs`）。

### 特徴量の群

| 群 | 中身 |
|---|---|
| A：選択肢の後の手 | DP の値（`A_ev`・`A_win`・`A_tenpai`・`A_in_dp`・`A_no_yaku`）、向聴・受け入れ（`A_shanten`・`A_ukeire`・`A_ukeire2`）、待ち（字牌・端・中、単騎、ロンの打点、ダマのツモの打点、筋）、門前、崩した手の聴牌への戻り、役の道（タンヤオ・染め手・対々和・役牌の対子・刻子）、手変わり、ドラ |
| B：動かした牌 | 牌の種類、ダブ風、ドラ、見えていない枚数、孤立牌、面子・対子を崩すか、筋の指標、タンヤオへの一歩、隣の牌の見えていない枚数・ドラなど 19 個。鳴きでは、鳴く牌（`B_*`）と鳴いた後に切る牌（`B_d_*`）、両面からのチー |
| O：選択肢の種類 | 立直、鳴き、崩す打牌、暗槓・加槓（大明槓は副露の選択肢で、印の列はない） |
| R：同じ判断の中での比較 | 最良の DP の値との比・差、2 段の受け入れの不足、向聴の後退 |
| X：掛け合わせ | 向聴の進み × 局の進み、鳴き × 局の進みの 2 乗 |

### 状態

判断の種類 × 手の型（七対子・染め手・役牌・一般）× 巡目（1〜6、7〜）× 他家の立直の有無（`/opp`・`/noopp`）。カンの判断では、立直後を別の状態にします。MLP には、状態の one-hot を入力に加えます（`Umlp::state_index`：状態の一覧が `/opp`・`/noopp` 付きのモデルは、他家の立直の有無で引く）。

## 4. 判断ごとの MLP

1 つの選択肢のスコアは、`w2 · relu(W1 [(x − mean) / std, onehot(状態)] + b1) + b2` です。最大のスコアの選択肢を打ちます。同点なら、選択肢の順で先のもの（鳴きなら見送り、立直ならダマ・崩す打牌が先、打牌なら牌の順）を選びます（`rules/universal_mlp.rs`）。

隠れ層は全モデル共通の `suzume::mlp::Hidden` です：1 層目 `W1`・`b1` のあとに、ファイルの `Wh`（行列のリスト）・`bh`（バイアスのリスト）で ReLU の層を何層でも重ねられます（ない場合は 1 層）。ベタオリ・回し打ち・状態予測も同じです。状況の入力を読むモデル（`sit_inputs` のあるファイル）は、判断の状況 21 個（`pf::situation`、8 節）を標準化して 1 層目の最後の列に加えます。判断の中のどの選択肢にも同じ値です。

下の表の隠れ層とモデルの外の切片は `T1_dep1` のものです。3 層の組の大きさはその次の表にあります。

| モデル | 範囲 | 入力の数 | 状態の数 | 隠れ層 | モデルの外の切片 |
|---|---|---|---|---|---|
| `discard12` | 打牌、打牌後の最小向聴 1〜2 | 39 | 16 | 32 | なし |
| `discard3` | 打牌、打牌後の最小向聴 3 以上 | 31 | 12 | 32 | なし |
| `tenpai` | 立直できない聴牌（手変わりの特徴量 `A_change_*` を含む） | 49 | 14 | 32 | なし |
| `riichi` | 立直が合法 | 48 | 16 | 32 | 立直の選択肢に、局の区分（東 1 +0.286、東 2〜4 +0.455、南 1〜3 +0.112、オーラス −0.895）とただ 1 人のトップ（−1.416） |
| `call` | チー・ポン・大明槓が合法 | 69 | 16 | 32 | チー・ポンの選択肢に、親 +0.267、ただ 1 人のトップ +0.364 |
| `kan` | 暗槓・加槓が合法（`kan_mlp`） | 54 | 20 | 8 | なし |

M・F の立直と副露（`riichi_M`・`call_M`・`call_F`）は、P のモデルと入力と状態が同じです。

3 層の組の隠れ層（層の数 × 幅）：

| ファイル | `T1_dep3` | `TN_dep3` |
|---|---|---|
| `discard_P_12` | 3 × 92 | 3 × 96 |
| `discard_P_3` | 3 × 72 | 3 × 72 |
| `discard_P_t` | 3 × 48 | 3 × 48 |
| `riichi_P` | 2 × 32 | 3 × 32 |
| `riichi_M` | 3 × 32 | 3 × 32 |
| `call_P`・`call_M`・`call_F` | 3 × 48 | 3 × 48 |
| `kan` | 3 × 12 | 3 × 12 |
| `discard_M` | 3 × 72 | 3 × 72 |
| `discard_F` | 3 × 64 | 3 × 64 |

`TN_dep3` の状態の数は `discard_P_t` が 16、`kan` が 19 です（`T1_dep3` は上の表と同じ）。

DP が手の価値を出せない局面（残りのツモがない、役のない聴牌）も、MLP が判断します。その行は DP の特徴量が 0（`A_in_dp = 0`）で、学習のデータにも同じ形で入っています。

カンの入力からは、鳴きの選択肢でしか 0 でない `B_chi_from_ryanmen`・`X_progress2_call` を外しています（大明槓の印の列 `O_daiminkan` は、どのモデルも使わなくなったので 2026-10-14 に U から削除）。カンの判断の「カンしない」の行が鳴きの選択肢になるのはカンと鳴きが同時に選べるときだけで、データでは 3 行以下しかなく、標準化の std が極端に小さくなるためです。

モデルの外の切片は、半荘の点数状況による調整です。MLP を固定したまま、前の版の suzume の半荘（rulebot 相手）のうち test 以外の局で推定しました。3 層の組では使いません（ファイルの `outside_bias` が null）。点数状況は、状態予測（`TN_*`）と、`TN_dep3` の手組みの状況の入力が読みます。

## 5. 学習

手組みのモデルは、教師（RLActor-225、鳴きあり）×4 の対局で、各判断の教師の方策に合わせて学習しました。

- 各判断には、押し引きの 3 状態（P・M・F）の HMM の事後確率を付け、その状態の事後確率で行に重みを付けます（P のモデルは P、M・F のモデルはその状態）。対局では、状態予測が 1 つの状態に決めてそのモデルを使います（8 節）。
- 東 1 局の組（`T1_*`）は東 1 局 10 万局、`TN_dep3` と状態予測の `TN_*` は半荘のデータです。
- 分け方は対局ごとに 7 : 2 : 1（train・valid・test）で、止めどきは valid の交差エントロピーです。
- 学習データの牌山はランダム牌山（split なし）です。

データ、推定の設定、手順、取り込みと一致の確認は、学習の段階を終えたので、このリポジトリには含めていません。新しいモデルを取り込むときは、JSON を `params/hand/<組>/`・`params/state/` に 2 節の表の名前で置きます。

## 6. 強さと速さ

自分たちの平均順位、天鳳の順位点（+90 / +45 / 0 / −135、1 半荘あたり）、素点とウマ 10-30（+30 / +10 / −10 / −30、オカ 20、1,000 点単位で 1 半荘あたり）。2v2 対 rulebot（カンをする `STANDARD`）、標準牌山（`wall_base 0`）の先頭 2,000 枚（2026-10-14）。

| モデル | 平均順位（SE 約 0.009） | 天鳳の順位点（SE 約 0.7） | ウマ 10-30（SE 約 0.36） |
|---|---|---|---|
| `suzume-mlp3`（規定） | 2.3609 | +10.72 | +5.50 |
| `suzume-mlp3-flat` | 2.3523 | +11.44 | +5.90 |
| `suzume-mlp3-avoid4` | 2.3548 | +11.45 | +5.34 |
| `suzume-mlp1` | 2.3702 | +9.90 | +5.10 |
| `suzume-mlp1-flat` | 2.3653 | +10.29 | +5.38 |

直接対決（2v2、標準牌山 5,000 枚。値は左のモデルの側。σ は牌山ごとの対の差を、その SE で割った値）：

| 組み合わせ | 平均順位 | 天鳳の順位点 | ウマ 10-30 |
|---|---|---|---|
| `suzume-mlp3` 対 `suzume-mlp3-flat` | 2.4891 / 2.5109（2.6σ） | +0.77（2.3σ） | +0.28（1.9σ） |
| `suzume-mlp3` 対 `suzume-mlp3-avoid4` | 2.4932 / 2.5068（1.3σ） | −0.04（0.1σ） | +0.65（3.2σ） |
| `suzume-mlp3-avoid4` 対 `suzume-mlp3-flat` | 2.5009 / 2.4991（0.2σ） | +0.40（1.0σ） | −0.50（2.4σ） |
| `suzume-mlp3` 対 `suzume-mlp1`（2,000 枚） | 2.4894 / 2.5106（1.3σ） | +0.94（1.5σ） | +0.39（1.3σ） |

- 3 層の組は 1 層の組より強い向き（1.3σ）。
- 手組みが `T1_dep3` の 2 つでは、半荘で学習した状態予測（`suzume-mlp3`）が東 1 局の状態予測（`suzume-mlp3-flat`）より上の向き（2.6σ）。対 rulebot の 2,000 枚では差が見えない（SE 約 0.009）。
- `TN_dep3` の手組み（`suzume-mlp3-avoid4`）は、1 位とラスが減って 2・3 位が増える。天鳳の順位点では他と同じか上の向き、素点とウマ 10-30 では下（2.4〜3.2σ）。
- 2026-10-14 より前の値は、以前の標準牌山（`wall_base 6172671062617`）のもので、直接は比べられない。

速さ（4 人とも同じ bot、200 牌山 × 3 回の中央値、2026-10-14）：`suzume-mlp3` 約 3,300 半荘/分、`suzume-mlp1` 約 4,900、rulebot 約 10,900。

結果を変えずに速くする仕組み（どれも同じ入力に同じ値を返すので、対局は変わらない）：

- DP の解を席ごと・局ごとに入力全体をキーに貯める（`sp::SolveCache`。鳴いた後の打牌の再利用もこれで行う）。
- 判断の U の行を `Ctx` に貯め、押し引きの特徴量（`hand_mlp`）と打牌の MLP で共有する。
- 判断の MLP のスコアを、その判断の間だけ `Ctx` に貯める（`Ctx::mlp_scores`。押し引きの特徴量、P の選択、カンの「カンしない」の行が同じスコアを使う）。
- 手牌だけで決まる値（向聴を保つ打牌、向聴を下げるツモ）をスレッドごとに貯める（`shanten::facts`。DP と受け入れの表が使う）。
- DP の表（ノード・ハッシュ表）の確保をスレッドごとに使い回し、ノードのキーは牌の出し入れで更新する（`dp.rs`）。
- MLP の 1 層目と深い層を、転置した重みで列ごとに全ユニットへ足す（`mlp.rs`。和の順と始めの値は単位ごとの和と同じ）。

## 7. ベタオリと回し打ち

ベタオリのモデル（`discard_F`）は、押し引き（8 節）の F の打牌と、`pf=0` のときのベタオリ（`fold=1`）が使います。回し打ちのモデル（`discard_M`）は同じ形で、押し引きの M の打牌が使います。

`fold=1`（`rules/fold.rs`）は、`pf=0` で、他家の立直があり、自分は立直しておらず、打牌後の最小向聴が `fold_shanten`（既定 1）以上のとき、ベタオリのモデル（`fold_model.rs`）で打牌を選びます。押し引きは判断しません（入る条件を満たせば常にオリる）。

### モデル

- 打牌の牌種ごと・他家ごとの MLP（特徴量 38 個、`T1_dep1` は隠れ層 32、3 層の組は 3 × 64。`TN_dep3` は状況の入力も読む）。他家 3 人全員について、立直の有無に関わらず同じ MLP で採点します。立直していない他家は、早い打牌（6 打目まで）を宣言前の打牌とみなします。
- 牌種のスコアは、3 人のスコアのソフトな最小 −τ log Σ exp(−s / τ)（τ はモデルごとに学習した値）。最高の牌種を切ります（赤と普通の 5 があれば普通の方）。
- パラメータ（入力の名前の順、標準化、重み、組み合わせ方と τ、待ちである率の表、帯の境界、上限）は `params/hand/<組>/discard_F.json`（`"seats": "all"`、`"combine": "softmin"`）。

| 群 | 特徴量 |
|---|---|
| その他家への危険度 | 現物か、放銃パターン数の合計・両面・嵌張・辺張・双碰（log(1 + 数)）、単騎（見えていない枚数）。放銃パターンは見えていない枚数から数え、双碰は現物でない相手の対子が要る形、立直前に赤 5 を切った色の 5 は持たないとする |
| 河の読み | 早く（6 打目まで、リーチ前）切られた 2・8／3・7／4・6 の外側、宣言牌の外側スジ、その他家にとっての役牌（オタ風 0・役牌 1・ダブ風 2）、同じ色の捨て牌の数、同じ色を最初に捨てた順番 |
| その他家の手の見え方 | 立直、副露数（暗槓を含む）、副露のドラ数（赤を含む）、親、捨て牌の数、役牌のポンの数、副露が 1 色（字牌可）・タンヤオ・チャンタ |
| 牌の種類 | 字牌、1・9、2・8、ドラ |
| 手 | 向聴の悪化、最善の打牌後の向聴数、手組みの MLP のスコア（最大との差。聴牌の手はダマ・崩す打牌を含む）、手に持つ枚数、巡目 min(自分の巡目, 18) / 18 |
| 残る安全牌 | 安全牌に換算した残りの枚数（待ちである率から）、それが残りツモ回数以上か |
| 他家 | 他の 2 人への待ちである率の見積もりの合計、他の 2 人のうち現物である人の割合、最後に切られてから何打牌前か（合わせ打ち） |

待ちである率は、放銃パターン数の帯（0・1・2〜3・4〜6・7〜12・13〜25・26〜40・41〜）× 自分の巡目の帯（1〜6・7〜12・13〜）の表で、立直者の実際の待ちから求めました。

- ベタオリのモデルは、F の状態の自分の打牌（向聴は問わない）で、F の事後確率で重み付けして学習しました。回し打ちのモデル（`discard_M`）は、同じ形で M の状態の打牌で学習しました。

## 8. 押し引き（`pf=1`）

`pf=1` は、自分の手番の打牌（立直しておらず、立直の宣言牌でもなく、合法な牌種が 2 種類以上）ごとに、押す（P）・回す（M）・オリる（F）の状態を予測し、状態ごとのモデルで打ちます（`src/rust/suzume/pf.rs`、`rules/fold.rs` の `PfDiscard`）。`fold` と `fold_shanten` は使いません。

| 判断 | P | M | F |
|---|---|---|---|
| 打牌（`discard_P_12`・`discard_P_3`・`discard_P_t`） | 手組みの MLP | 回し打ち（`discard_M`） | ベタオリ（`discard_F`） |
| 立直できる判断 | `riichi_P` | `riichi_M` | `riichi_M` |
| チー・ポン | `call_P` | `call_M` | `call_F` |
| 大明槓（副露の選択肢） | `call_P` | `call_M` | しない |
| 暗槓・加槓 | `kan` | `kan` | しない |

- 状態は、予測した P・M・F の確率が最も高いもの（同点は P、次に M）。
- 副露の判断は、自分の直前の手番の状態を使う（局の始めは P）。自分の立直後は状態を予測せず、カンはカンの MLP が決める。
- 回し打ちのモデルは、ベタオリのモデルと同じ形（特徴量 38 個、他家 3 人をソフトな最小で組み合わせる）で、M の判断で学習したもの（Viterbi の M、M の事後確率で重み付け）。
- F の立直に `riichi_M` を使うこと、カンのモデルを状態で分けずに学習することは仕様（`riichi_F` はない）。
- 学習では状態の事後確率で行に重みを付け、対局では 1 つの状態に決めて打つ（設計どおり）。

### 状態予測モデル

- 入力：ベタオリのモデルと同じ特徴量 38 個を、他家 3 人 × 合法な牌種の行ごとに MLP に通し、平均と最大でまとめて、P・M・F の確率を出します。
- 状況の入力（`TN_*`）：判断ごとの状況 21 個（`pf::situation`）を、各行の 1 層目に同じ値で足します。局（東 1〜南 4 の one-hot、西入は南 4）、本場、供託、順位（one-hot、同点は席の小さい方が上）、持ち点、トップ・ラス・一つ上・一つ下との点差（いなければ 0）とその有無。点数は 25,000 で割り、train で標準化。
- 教師：HMM の P・M・F の事後確率との交差エントロピー。`TN_*` は教師 ×4 の半荘 1 万の自分の手番の打牌 497 万件、`T1_*` は東 1 局のデータで学習しました。
- 規定の `TN_dep3` は 3 層 × 86（test の交差エントロピー 0.6649、ラベルのエントロピー 0.43）。

## 10. 既知の課題
